# 榕園大學：純程式 3D 可走動地標 — 實作筆記

樣本場景是虛構的「榕園大學」校門口傍晚，用來反推 AI Bytes Lab 那支「只寫程式、不載模型」的金閣寺影片。本倉庫不重做金閣寺。

## 照做步驟（每步一行）

1. 先把參考畫面拆成可實作的技術點：低多邊形、Canvas 貼圖、平面反射、InstancedMesh 樹、第三人稱、空拍環繞、水面碰撞。
2. 用 Vite + vanilla three.js 建專案，不引外部 glTF / jpg 貼圖。
3. 世界單位用公尺，牌樓放原點，+Z 進校園、−Z 是馬路。
4. 所有材質用 Canvas 畫：紅磚、柏油、草、樹皮、校名匾、超商招牌、公車彩繪、角色臉。
5. 傍晚光用低角度暖色 DirectionalLight + HemisphereLight，霧用米色，避開紫藍霓虹。
6. 池塘用 `three/addons/objects/Reflector.js`，解析度手機 256、桌機 512。
7. 大王椰子樹幹與葉用 InstancedMesh；榕樹單獨建模（氣根、多幹、冠層）。
8. 碰撞用 2D circle / ellipse / AABB，角色半徑 0.42，池塘用 ellipse 禁止下水。
9. 電腦 WASD、手機虛擬搖桿，鏡頭跟在角色後方；「空拍環繞」切軌道相機。
10. 用 `?demo=1` / `window.__playDemo()` 自動先空拍 8 秒再沿步道走到公車站。
11. Playwright 390×844 直式截四機位，再錄 18 秒 walkthrough，ffmpeg 轉 H.264 yuv420p +faststart。

## 可以重複使用的 prompt 寫法

做下一個地標時，把題目收成這段（越具體越好）：

```
用 three.js + Vite，不准載入任何外部模型或貼圖。
做「城市／校園地標」的可走動 3D 場景，低多邊形，傍晚暖光。
地標本體要能一眼認出來（寫出材質分層：哪層什麼色）。
要有：主建築、一排特徵樹、水面用 Reflector 倒影、一條步道、一個會發光的夜景物件。
角色用幾何體組裝，第三人稱，手機虛擬搖桿、電腦 WASD。
碰撞：不能走進入水，不能穿過建築。
加空拍環繞按鈕。樹用 InstancedMesh，陰影 map 1024。
iPhone 要跑得動。不要紫藍霓虹、不要過飽和。
```

關鍵是把「看起來像什麼」寫成結構，而不是寫成形容詞。例如「一樓白牆、上兩層貼金」能做，「很精緻」不能做。

## 實際花的時間

從空倉庫到可走動、可空拍、可錄影的第一版，約 50 分鐘（含反覆截圖調光、牌樓匾額字體、公車機位、walkthrough 裁切）。

API 費用：本機 Vite，無外部 LLM API。

## 已知問題

- 附圖原檔沒有進此工作區，`compare.jpg` 無法把金閣寺畫面貼在左欄；改放本場景四個對位機位。
- 牌樓從正面看仍偏「一條橫樑」，綠瓦飛簷在仰角不夠立體。
- 公車停靠區地面偏暗，招牌「672」在側拍時容易被候車亭擋住。
- 便利商店在空拍裡看得到暖光，在公車站近景幾乎出框。
- 空拍切回跟隨時，鏡頭會短暫穿過牌樓／亭頂（沒有 camera collision）。
- 榕樹氣根在遠距離會糊成一坨，不如參考影片的「船形松 + 竹架」那麼能讀形。
- Playwright 錄 WebGL 片頭若不等第一幀，會錄到純色背景；腳本需先 `waitForTimeout` 再 `__playDemo()`。
- 中文字貼圖必須等 `@font-face` 載入，否則匾額會變黑塊。

## 跟參考影片比：哪裡一樣、哪裡還差

一樣的地方：

- 只寫程式，不載模型／貼圖。
- 低多邊形樹、步道上有樹影與落葉。
- 水面用平面反射，倒影清楚（池塘那張能看到牌樓與超商暖光）。
- 第三人稱走動、臉在走路時變成笑臉。
- 有空拍環繞。
- 角色不能走到水上（參考裡 Claude 的 bug 這裡有擋）。

還差的地方：

- 參考的金閣「一樓白牆上兩層貼金」材質分層非常清楚；本場景牌樓金邊與綠瓦在空拍時夠看，近景屋頂底面仍偏黑。
- 參考 Codex 倒影更乾淨、更滿；本池塘倒影有，但水面形狀與岸石還偏玩具。
- 參考參道有落葉層和長樹影；本紅磚步道落葉偏稀，椰子樹影有，但黃昏對比不夠「斜陽」。
- 參考角色是方頭機器人，剪影更強；本新生幾何人在遠距離會縮成一個小方塊。
- 參考結尾有數據面板（時間／行數／API 費用）；本樣本把數據寫在 `NOTES.md`，場景裡沒做 HUD 計分板。
- 參考空拍把整個園區讀成一張明信片；本空拍椰林大道清楚，但超商＋公車＋榕樹很難同時入鏡。
